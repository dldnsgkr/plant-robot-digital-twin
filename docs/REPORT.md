# 프로젝트 보고서 — 플랜트 4족 보행 로봇 Digital Twin

> 과제 요구사항: [REQUIREMENTS.md](REQUIREMENTS.md) · 계획: [PLAN.md](PLAN.md)
> · 아키텍처: [ARCHITECTURE.md](ARCHITECTURE.md)

## 1. 시스템 개요

가상 발전소(복도 45×3.5×4m + 공장 25×18×7m)에서 Unitree Go2 모델 로봇이
험지 보행, 아날로그 게이지 판독, 열화상 점검, 가스 누출원 추적, 자율 복귀를
수행하고 웹 관제 대시보드로 실시간 감시하는 Digital Twin.

- 스택: **ROS 2 Jazzy + Gazebo Harmonic** (Docker, Apple Silicon arm64
  네이티브 — 선정 경위와 Humble 불가 판정은 PLAN.md §2.3)
- 실행: `docker compose up` 후
  `ros2 launch /ws/src/plant_dt/simulation/launch/plant_dt.launch.py mission:=true`

## 2. 모듈별 구현과 측정 결과

### Module 1 — Locomotion

| 항목 | 구현 | 측정 |
|---|---|---|
| 보행 | 위상 오실레이터 + 사이클로이드 스윙 + 해석적 3DOF IK, trot/험지/crawl 게이트 | 전진 0.17m/s 직진(요 홀드), 측방·대각·후진·회전 전 방향 정상 |
| 지형 인지 | LiDAR→중력정렬 2.5D Elevation Map(4×4m/5cm), EMA+자기몸 마스킹+감쇠, 평탄도 foothold 평가 | 지면 σ=0.007m, 벽·장애물 검출 |
| 지형 적응 | 전방 장애물 높이→스윙 리프트·몸높이 상승, 험지 게이트 자동 전환 | 낮은 장애물(≤0.12m) 통과 설계, 굵은 파이프는 우회 대상(운용 분리) |
| MPC (stage2) | 축별 LIP condensed MPC(해석해 ~2µs), 예측구간 튜닝 실험 | N=10(1.0s) 최적 — 5초 스펙 구간은 이득 없음(TUNING.md 표) |
| Fall Recovery | IMU 판정(1.0rad/0.3s) + TUCK→펄스킥→EXTEND 상태기계, 뒤집힘 대응(thigh 2.9rad 등넘김) | 100~300Nm 외란 전도에서 자동 기립 검증 |

### Module 2 — Inspection AI

| 항목 | 구현 | 측정 |
|---|---|---|
| 게이지 판독 | CLAHE→HoughCircles→HSV 바늘 히스토그램→각도-수치 변환→시간 중앙값 | 청정 FS 1.2%/95%ile 1.9% (620건), **열화(저조도+블러+노이즈) 조건에서도 1.9%** — 목표 5% 달성 |
| 열화상 | Depth 픽셀별 3D 복원 기반 온도 합성(가림 자연 반영) + 3cm 베이스라인 픽셀별 깊이 재투영 정합 | 배관 이음매(90°C 설정) OVERHEAT 68.6°C 검출·정합 |
| 순찰 경로 | 정면각²+거리편차² 비용, 충돌·가림 제약, TSP(NN+2-opt) | 게이지 관측점이 수동 최적 위치와 일치(교차 검증), 4개소 101.8m |

### Module 3 — Gas/Safety

| 항목 | 구현 | 측정 |
|---|---|---|
| 확산 시뮬 | 가우시안 플룸(풍하 σ 성장·희석·돌풍±20%) + 풍향계 | 중심선 단조 증가 16→56ppm, 최대점 풍하 2.4m |
| Source Seeking | CAST/CLIMB(최소제곱 구배)/SURGE(풍상+횡풍 센터링)/RETURN(최고농도 백트래킹) + LiDAR 회피 | (5,-2)→발견 84s, 농도 13.9→52.3ppm 단조 상승, 장애물 회피 작동, **플룸 최대점 기준 2.1m**(소스 기준 4.5m — 농도 최대가 풍하 2.4m에 형성되는 플룸 물리의 계측 한계) |
| 자율 복귀 | 배터리·통신음영 트리거, A*(0.25m 격자·0.4m 팽창), 헤딩 조향 추종 | 4 시작점 경로 전부 성공, 통합 데모 도킹 오차 0.50m |

### 통합 (Phase 5)

통합 시나리오 실측 (한 명령 실행, 완전 자율):

```
복도 스폰 → 17m 자율주행(187s) → 게이지 관측점 도착 → 방향 정렬(3.7s)
→ 판독 3.26bar(116건) → 공장 이동 → 배터리 20% → 자율 복귀 자동 발동
(미션 제어권 양보) → A* 19-waypoint → 도킹(오차 0.50m) → 재충전 → 종료
```

관제 대시보드(rosbridge+roslibjs): 실시간 위치·궤적·가스 플룸 오버레이·
배터리·판독값·과열 배지·이벤트 로그 — 캡처: `docs/images/dashboard_*.png`

## 3. 문제 해결 기록 (심층 인터뷰 대비)

**① 타이머 중첩 버그 — '유령 기생 결합'의 전말 (최대 난제)**
보행이 시간이 지날수록 열화(측방→후진, 후진→스핀)했고, 격리 실험으로
결합을 정량화하며 속도 PI 폐루프·축정렬 주행 등을 설계했다. 그러나 진짜
원인은 디버그 타이머 추가 시 `__init__` 잔여 코드가 메서드 안으로 흡수돼
**2초마다 100Hz 제어 타이머가 복제**된 것(실측 44개 누적). 수정 후 전 방향
보행이 정상화됐고 통합 시나리오가 완주됐다. 교훈: 시간 경과형 제어 이상은
실행 기반(타이머·스레드)의 누적 결함을 먼저 의심할 것.

**② 자기 관측 양성 피드백 (Elevation Map)**
스윙 중 들어올린 발을 LiDAR가 장애물로 인식 → 리프트 증가 → 더 높이 든 발
재인식의 발산 루프. 로봇 풋프린트 마스킹으로 해결.

**③ 위치제어 지지에서의 LIP-MPC 모델 불일치 (stage2)**
CoP 이동→중력모멘트 가정이 강성 고정 지지에서는 성립하지 않아 자기 가진
전도 유발. 반복 A/B로 확인, 기본 비활성 처리 — 토크 제어 기반 stage3의
필요성 근거 (TUNING.md).

**④ 브리지 데이터 소실**
Pose_V→TFMessage 브리지가 엔티티 이름을 소실해 하위 노드가 무효 데이터로
동작. OdometryPublisher 플러그인 전환으로 해결 — 무효했던 실험 결과를
소급 정정한 과정 포함.

**⑤ 메서드 삽입 위치 실수의 재발과 방어**
①의 타이머 버그와 동형의 실수(메서드를 `__init__` 중간에 삽입 → 잔여
초기화 코드가 메서드 몸체로 흡수)가 seeker에서도 재발해 노드가 무증상
비활성이 됐다. '시작 로그 부재/중복'을 1차 스모크 신호로 삼는 점검 습관과,
초기화 코드를 메서드 정의보다 앞에 모으는 규약으로 방어.
