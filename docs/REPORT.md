# 프로젝트 보고서 — 플랜트 4족 보행 로봇 Digital Twin

> 과제 요구사항: [REQUIREMENTS.md](REQUIREMENTS.md) · 계획: [PLAN.md](PLAN.md)
> · 아키텍처: [ARCHITECTURE.md](ARCHITECTURE.md)

## 1. 시스템 개요

가상 발전소(복도 45×3.5×4m + 공장 25×18×7m)에서 Unitree Go2 모델 로봇이
험지 보행, 아날로그 게이지 판독, 열화상 점검, 가스 누출원 추적, 자율 복귀를
수행하고 웹 관제 대시보드로 실시간 감시하는 Digital Twin.

- 스택: **ROS 2 Jazzy + Gazebo Harmonic** (Docker, Apple Silicon arm64
  네이티브 — 선정 경위와 Humble 불가 판정은 PLAN.md §2.3)
- 실행: `docker compose up` 후
  `ros2 launch /ws/src/plant_dt/simulation/launch/plant_dt.launch.py mission:=true`

## 2. 모듈별 구현과 측정 결과

### Module 1 — Locomotion

| 항목 | 구현 | 측정 |
|---|---|---|
| 보행 | 위상 오실레이터 + 사이클로이드 스윙 + 해석적 3DOF IK, trot/험지/crawl 게이트 | 전진 0.17m/s 직진(요 홀드), 측방·대각·후진·회전 전 방향 정상 |
| 지형 인지 | LiDAR→중력정렬 2.5D Elevation Map(4×4m/5cm), EMA+자기몸 마스킹+감쇠, 평탄도 foothold 평가 | 지면 σ=0.007m, 벽·장애물 검출 |
| 지형 적응 | 전방 장애물 높이→스윙 리프트(상한 0.05)·험지 게이트 자동 전환 | **7cm 파이프 통과 실증**(넘어짐 0, 이후 복도 문 지나 공장까지 21.6m 연속 진입). 격리 실험으로 리프트≥0.10 시 트로트 자체가 불안정함을 규명 — 12cm급은 우회 대상, 높은 스윙 안정화는 stage3 접촉 제어 과제 |
| MPC (stage2) | 축별 LIP condensed MPC(해석해 ~2µs), 예측구간 튜닝 실험 | N=10(1.0s) 최적 — 5초 스펙 구간은 이득 없음(TUNING.md 표) |
| Fall Recovery | IMU 판정(1.0rad/0.3s) + TUCK→펄스킥→EXTEND 상태기계, 뒤집힘 대응(thigh 2.9rad 등넘김) | 100~300Nm 외란 전도에서 자동 기립 검증 |

### Module 2 — Inspection AI

| 항목 | 구현 | 측정 |
|---|---|---|
| 게이지 판독 | CLAHE→HoughCircles→HSV 바늘 히스토그램→각도-수치 변환→시간 중앙값 | 청정 FS 1.2%/95%ile 1.9% (620건), **열화(저조도+블러+노이즈) 조건에서도 1.9%** — 목표 5% 달성 |
| 열화상 | Depth 픽셀별 3D 복원 기반 온도 합성(가림 자연 반영) + 3cm 베이스라인 픽셀별 깊이 재투영 정합 | 배관 이음매(90°C 설정) OVERHEAT 68.6°C 검출·정합 |
| 순찰 경로 | 정면각²+거리편차² 비용, 충돌·가림 제약, TSP(NN+2-opt) | 게이지 관측점이 수동 최적 위치와 일치(교차 검증), 4개소 101.8m |

### Module 3 — Gas/Safety

| 항목 | 구현 | 측정 |
|---|---|---|
| 확산 시뮬 | 가우시안 플룸(풍하 σ 성장·희석·돌풍±20%) + 풍향계 | 중심선 단조 증가 16→56ppm, 최대점 풍하 2.4m |
| Source Seeking | CAST/CLIMB(최소제곱 구배)/SURGE(풍상+횡풍 센터링)/RETURN(최고농도 백트래킹) + LiDAR 회피 | (5,-2)→발견 84s, 농도 13.9→52.3ppm 단조 상승, 장애물 회피 작동, **플룸 최대점 기준 2.1m**(소스 기준 4.5m — 농도 최대가 풍하 2.4m에 형성되는 플룸 물리의 계측 한계) |
| 자율 복귀 | 배터리·통신음영 트리거, A*(0.25m 격자·0.4m 팽창), 헤딩 조향 추종 | 4 시작점 경로 전부 성공, 통합 데모 도킹 오차 0.50m |

### 통합 (Phase 5)

통합 시나리오 실측 — **전 사슬 완전 자율 완주** (한 명령 실행, 17분 7초):

```
t=0     복도 스폰 → A* 순찰 주행
t=110s  게이지 관측점 도착 → 방향 정렬(5s) → 판독 4.82bar (115건)
t=354s  공장 도착 → 가스 알람 발령 → source_seeker에 제어권 위임
t=482s  누출원 발견 보고: (-6.2, 5.7) C=59.9ppm — 실제 소스에서 2.8m
t=911s  배터리 20% → 자율 복귀 자동 발동 (21-waypoint A*)
t=1027s 충전 스테이션 도킹 (오차 0.50m) → 재충전 → 미션 종료
```

게이지 도착 110/111초로 2회 연속 재현(안정성), 통신음영 가드 오발동 0.
재현성 확보 과정에서 3중 원인(차선 침범 파이프, 조용히 실패한 리프트 캡
패치, effort 인터페이스 등록 부작용)을 규명·수정 — §3 문제 해결 기록 참조.

관제 대시보드(rosbridge+roslibjs): 실시간 위치·궤적·가스 플룸 오버레이·
배터리·판독값·과열 배지·이벤트 로그 — 캡처: `docs/images/dashboard_*.png`, `docs/images/scada_*.png` (가스 누출원 발견: `scada_gas_found.png`)

### 제공 3D 에셋 적용 (Gazebo 비주얼)

과제 제공 에셋(Unity `.unitypackage`)의 FBX 를 OBJ 로 변환(`simulation/models/plant_assets/convert.py`)해
공장·복도·가스탱크·팔레트의 visual 로 교체했다. 충돌 형상은 검증된 박스를 유지하고, 라이다가
보는 visual 과 물리 충돌면이 일치하도록 복도 메시를 스케일(x 0.926 / y 0.92)했으며, 박스 월드의
경로와 겹치는 메시 부분(동측 칸막이벽·펜스, 남벽 앞 설비, 복도 바닥 플레이트)은 변환 단계에서
절단했다. 검증: 로봇 높이 레이캐스트로 미션 경유점 12곳의 장애물 없음 확인, RTF 박스 월드와 동일,
통합 미션 재실행 완주(게이지 115s, 공장 도착 397s, 도킹 오차 0.50m).
캡처: `docs/images/gazebo_assets_{corridor,factory,gastank}.png`

## 3. 문제 해결 기록 (심층 인터뷰 대비)

**① 타이머 중첩 버그 — '유령 기생 결합'의 전말 (최대 난제)**
보행이 시간이 지날수록 열화(측방→후진, 후진→스핀)했고, 격리 실험으로
결합을 정량화하며 속도 PI 폐루프·축정렬 주행 등을 설계했다. 그러나 진짜
원인은 디버그 타이머 추가 시 `__init__` 잔여 코드가 메서드 안으로 흡수돼
**2초마다 100Hz 제어 타이머가 복제**된 것(실측 44개 누적). 수정 후 전 방향
보행이 정상화됐고 통합 시나리오가 완주됐다. 교훈: 시간 경과형 제어 이상은
실행 기반(타이머·스레드)의 누적 결함을 먼저 의심할 것.

**② 자기 관측 양성 피드백 (Elevation Map)**
스윙 중 들어올린 발을 LiDAR가 장애물로 인식 → 리프트 증가 → 더 높이 든 발
재인식의 발산 루프. 로봇 풋프린트 마스킹으로 해결.

**③ 위치제어 지지에서의 LIP-MPC 모델 불일치 (stage2)**
CoP 이동→중력모멘트 가정이 강성 고정 지지에서는 성립하지 않아 자기 가진
전도 유발. 반복 A/B로 확인, 기본 비활성 처리 — 토크 제어 기반 stage3의
필요성 근거 (TUNING.md).

**④ 브리지 데이터 소실**
Pose_V→TFMessage 브리지가 엔티티 이름을 소실해 하위 노드가 무효 데이터로
동작. OdometryPublisher 플러그인 전환으로 해결 — 무효했던 실험 결과를
소급 정정한 과정 포함.

**⑤ 메서드 삽입 위치 실수의 재발과 방어**
①의 타이머 버그와 동형의 실수(메서드를 `__init__` 중간에 삽입 → 잔여
초기화 코드가 메서드 몸체로 흡수)가 seeker에서도 재발해 노드가 무증상
비활성이 됐다. '시작 로그 부재/중복'을 1차 스모크 신호로 삼는 점검 습관과,
초기화 코드를 메서드 정의보다 앞에 모으는 규약으로 방어.

### 제공 에셋 메시가 로봇 카메라에서 흰색으로 나온 문제

**증상**: GUI(ogre1)에서는 텍스처가 보이는데 로봇 전방 카메라(센서 렌더러 ogre2)에서는 벽·천장이
순백으로 나옴. 라이다는 같은 메시를 정상 감지(벽 ±1.64m).
**배제한 가설**: 텍스처 예산 초과(1024²로 축소해도 동일), MTL 밝기·광택값(변경해도 픽셀 동일),
알파 채널(전부 RGB), 뒷면 컬링(양면화해도 동일), SDF `<material>` 강제 지정(동일).
**원인**: 변환기(trimesh)가 OBJ에 정점 법선(`vn`)을 쓰지 않았음. ogre1은 법선을 자체 계산하지만
ogre2 PBR 은 법선이 없으면 조명 결과가 깨져 흰색이 된다.
**해결**: `include_normals=True` 로 재내보내기. 교훈: 두 렌더러가 다른 결과를 낼 때는
메시 데이터(법선·UV·와인딩) 자체를 먼저 의심하고, 대조 실험은 픽셀 단위로 비교한다.

## 4. 남은 항목·확장 계획

- stage3 Convex MPC(C++): **부분 달성** — SRBD 응축 MPC(N=10, 마찰원뿔 제약,
  EiquadprogFast 25Hz 1400회+ 무실패) + 순수 토크 제어로 기립·정지 유지
  (z=0.33, GRF 비대칭 분배 fz≈mg) 실증. 한계(기립 초기조건 의존, 수평 지속
  외란 시 '자세가중>위치가중 → QP가 fz 최소화 선택' 구조 규명)와 해법은
  stage3_convex_mpc_cpp/STATUS.md
- Nav2 정식 통합(현재 자체 A*)
- **계단 등반 미달성 분석**: 계단(단높이 0.18m)은 실측 발들기 한계(0.07m —
  격리 실험에서 스윙 리프트 0.10부터 평지 트로트도 붕괴)의 약 3배를 요구한다.
  높은 스윙이 무너지는 기전은 개루프 위상 타이밍+위치제어 구조에서 스윙
  진폭 증가 → 관성 반동·추종 지연·착지 타이밍 오차 증폭이며, 계단은 여기에
  ① 발마다 다른 지면 높이(단일 몸높이 평면 IK 가정 위배), ② 몸통 피치
  (~27°) 필요(수평 유지 자세보정과 상충), ③ 단깊이 0.35m 내 발배치 정밀도
  (foothold 평가는 구현됐으나 다리별 스텝 연결 미구현)가 추가된다.
  즉 '튜닝'이 아니라 제어 세대 전환 문제로, 해법은 접촉 감지 기반 토크
  제어+접촉 스케줄 MPC(stage3의 완성) 또는 강화학습(보너스③) —
  실기 Go2/ANYmal의 계단 등반도 이 두 계열이다. 중간 지대로 crawl(3점
  지지 정적 보행)의 높은 리프트 허용 가능성은 미검증 시도로 남긴다.
- 보너스: 웹 대시보드 ✓ / **다중 로봇 협업 ✓** — go2(복도)·go2b(공장) 구역
  분할 동시 순찰 실증(2호기는 네임스페이스 분리 ros2_control + 경량 URDF,
  A* 구역 순찰 루프, 대시보드 색상 구분 표시. 단일 Gazebo 내 이중
  gz_ros2_control의 두 함정 — 로드 겹침 시 CM 정지, robot_description 부재 시
  플러그인 스레드 블로킹으로 시뮬 전체 정지 — 를 실측으로 규명해 순차 기동
  + 전용 rsp로 해결) / RL 보행·클라우드 관제(EC2 구간, 미착수)
