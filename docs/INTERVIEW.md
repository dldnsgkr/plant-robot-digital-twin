> 과제 §9의 질문에 대해, 본 레포의 실제 구현·측정을 근거로 정리한 답변.

## Module 1 — Locomotion

**Q. 험지 센서 데이터의 노이즈를 어떻게 걸러 Elevation Map을 만들고, 발 디딤 위치는 어떻게 결정하는가?**
LiDAR 포인트를 IMU 롤/피치로 중력 정렬한 뒤 로봇 중심 4×4m/5cm 격자에 셀별 최대 높이로 투영하고, 세 단계로 노이즈를 처리한다: ① 시간 EMA(α=0.4)로 빔 노이즈 완화, ② 관측 카운트 2회 미만 셀 무효화 + 시간 감쇠로 이동 중 구식 데이터 만료, ③ 로봇 풋프린트 마스킹 — 스윙 중 들어올린 자기 발을 장애물로 재인식하는 양성 피드백(실측으로 발견)을 차단. 발 디딤은 다리별 명목 착지점 주변 15cm에서 "3×3 높이 분산(평탄도) + 명목점 거리²" 비용 최소 셀을 선택한다. 결과 지면 표준편차 0.007m.
→ `module1_locomotion/terrain_mapping/elevation_map.py`

**Q. 외란 시 MPC는 상태 변화를 어떻게 감지하고 다음 구간의 발 토크를 어떻게 계산하는가?**
두 단계로 구현했다. stage2(Python, LIP)는 오도메트리 몸속도 오차를 상태로 condensed QP를 풀어 CoP(발 배치) 오프셋을 낸다. 그러나 반복 A/B로 **위치제어 지지에서는 LIP 가정(CoP→중력모멘트→가속)이 성립하지 않음**을 확인했고, 이 결론대로 stage3(C++)에서 토크 제어로 전환했다: 13-상태 SRBD를 N=10(0.4s)으로 응축하고 지면반력(GRF) 시퀀스를 마찰원뿔·수직력 제약 QP(EiquadprogFast, 25Hz 1400회+ 무실패)로 최적화, 200Hz에서 τ=−JᵀRᵀf로 관절 토크에 매핑한다. 기립 균형에서 GRF 비대칭 분배(fz 합≈체중, CoM 오프셋 자동 반영)를 실증했다.
→ `stage2_simple_mpc_py/TUNING.md`, `stage3_convex_mpc_cpp/`

**Q. 넘어짐 판정과 기립 시퀀스는?**
IMU 쿼터니언에서 롤/피치를 추출해 |각도|>1.0rad가 0.3초 지속되면 넘어짐으로 판정한다(순간 충격 오검출 방지). 시퀀스는 상태기계: TUCK(웅크림, 관성 최소화) → RIGHT(비대칭 펄스 킥 — 뒤집힌 경우 thigh를 2.9rad까지 돌려 다리를 등 너머로 넘겨 발이 바닥을 밀게 하고, 0.25s 급신전/수축 5회로 흔들림을 축적해 굴림, 실패 시 반대쪽 재시도) → EXTEND(TUCK 경유 램프로 기립 — 킥 자세에서 직행하면 재전도). 300Nm 외란 전도에서 자동 기립 검증.
→ `module1_locomotion/fall_recovery/fall_recovery.py`

**Q. (심층) MPC 예측 구간이 안정성에 미치는 영향과 선정 근거는?**
지연 40ms+노이즈를 포함한 폐루프 시뮬로 N∈{3..80}을 스윕했다: N=3은 포화 입력 하 회복 여유를 과소평가해 정착 1.48s로 느리고, N=10(1.0s)이 0.86s로 최적, 스펙의 5초 구간(N=50)은 이득이 없으며(1.06s) N=80은 5.32s로 악화된다. 기준: 구간이 시스템 시정수 √(h/g)≈0.18s의 약 5배를 넘으면 성능이 포화하고, 지연·포화가 있으면 과도한 구간은 초기 스텝의 이득을 희석한다. 풀이는 사전 계산 이득으로 ~2µs라 실시간성이 아닌 순수 제어 성능으로 선정했다.
→ `stage2_simple_mpc_py/TUNING.md` (표 포함)

**Q. (심층) 보행 모드 전환 기준은?**
trot(대각 2쌍, duty 0.5, 0.5s)이 기본, elevation map의 전방 장애물 높이가 3cm를 넘으면 험지 모드(duty 0.62, 주기 0.9s — 3발 근접 지지·보폭 증가)로 자동 전환하고 스윙 리프트·몸높이를 장애물 높이에 맞춰 올린다. crawl(duty 0.75)은 파라미터로 선택. 전환은 위상 연속(주기만 변경)이라 충격이 없다.
실증: 7cm 파이프를 넘어짐 없이 통과 후 21.6m 연속 주행(문 통과 포함).
격리 실험으로 스윙 리프트 0.10 이상에서는 평지에서도 트로트가 무너짐을
확인해 상한을 0.05로 설계했다 — 통과(≤7cm)/우회(그 이상)의 운용 분리 근거.
→ `stage1_gait_controller/gait_controller.py` GAITS/`_on_elev`

## Module 2 — Inspection AI

**Q. 흔들림·조명 변화에서 바늘·숫자를 어떻게 구분·추출하는가?**
전처리 CLAHE(국소 대비 향상)+가우시안 → HoughCircles로 다이얼 검출 → 원 내부에서 HSV 빨강 마스크(저조도에서도 Hue 유지 — S/V 하한을 낮게)로 바늘 후보를 얻고, 실패 시 어두운 픽셀 폴백. 중심 기준 방사 픽셀의 각도 히스토그램 최빈 방향으로 바늘각을 정하고(반경 0.15~0.85r만 사용해 중심축·외곽 눈금 배제), 5프레임 중앙값으로 순간 오독을 제거한다. 검증: 저조도 0.35+회전 모션블러 9px+노이즈 σ8을 주입해도 오차 95%ile FS 1.9%(목표 5%).
→ `gauge_reader/gauge_reader.py`, `image_degrader.py`, `eval_accuracy.py`

**Q. 열화상·실화상 위치 오차를 수학적으로 어떻게 보정했는가?**
두 카메라의 외부 파라미터(URDF 실측: 3cm 횡 베이스라인)를 이용한 픽셀별 깊이 재투영으로 정합한다: 열화상 픽셀 (u,v)와 그 픽셀의 깊이 d로 3D 점 p=((u−cx)/f·d, (v−cy)/f·d, d)를 복원하고, RGB 카메라 좌표로 평행이동 후 K_rgb로 재투영한다. 평면 가정 호모그래피와 달리 시차가 깊이에 반비례하는 것을 픽셀 단위로 정확히 처리하므로 근거리·원거리가 동시에 맞는다. 60°C 초과 영역에 OVERHEAT 박스를 표시하며, 배관 이음매(90°C 설정)에서 68.6°C 검출을 확인했다.
→ `thermal_fusion/thermal_fusion.py` (도입부 수식 주석)

**Q. '인식이 가장 잘 되는 각도·거리'의 가중치/비용은?**
cost = w_ang·(정면 법선과의 각도)² + w_dst·(거리−d_opt)², 유효성 하드 제약으로 장애물 충돌(0.4m 여유)과 시선 가림(선분-원 교차)을 건다. d_opt는 다이얼이 프레임의 ~25%를 차지하는 거리(해상도-시야 균형). 각도²항은 사각 판독의 원근 왜곡을 반영한다. 검증: 산출된 게이지 관측점 (38.0, 0.22)가 판독 정확도 시험에서 수동 선정한 최적 위치와 일치했고, 통합 미션이 실제로 이 지점에서 3.26bar를 판독했다. 순회는 TSP(최근접+2-opt).
→ `patrol_planner/patrol_planner.py`

## Module 3 — Gas/Safety

**Q. 불규칙 확산에서 농도 구배로 방향을 어떻게 결정하는가? 국소최적 대응은?**
이동 궤적 8초 슬라이딩 윈도의 (x,y,C)에 최소제곱 평면을 적합해 ∇C를 추정하되, 위치 스프레드가 부족하면 기각한다. 난류로 구배가 요동하므로 4-모드 상태기계로 감싼다: 농도가 낮으면 CAST(확장 나선 탐색), 약한 신호에선 CLIMB(구배 상승), 플룸 내부(>12ppm, 히스테리시스 8s)에서는 구배 노이즈를 버리고 **풍향계 기반 풍상 SURGE + 구배의 횡풍 성분만으로 중심선 유지** — 플룸 추적의 표준 기법이다. 국소최적/플룸 이탈에는 RETURN: 최고 농도 기록 지점(월드 좌표)으로 백트래킹 후 재탐색. 검증: 84초에 발견 선언, 농도 13.9→52.3ppm 단조 상승, 발견점은 플룸 최대점 기준 2.1m(농도 최대가 소스 풍하 2.4m에 형성되는 플룸 물리의 계측 한계 — 개선안은 풍상 외삽).
→ `source_seeking/source_seeker.py`, `gas_simulation/gas_field.py`

**Q. 복귀 트리거와 장애물 회피 경로 계획은?**
트리거는 ① 배터리<20%(이동 0.25%/s·대기 0.05%/s 소모 모델) ② 통신 음영(복도 깊숙 x>48에 5초 체류 — 구역 밖에서 진입한 경우만 무장해 배치 직후 오발동 방지). 발동 시 월드 기하(벽+장애물 0.4m 팽창)를 0.25m 격자로 이산화해 A*(8방향)로 계획하고 0.75m 간격으로 솎아 헤딩 조향으로 추종한다. 통합 데모: 공장 이동 중 20% 도달 → 미션이 제어권 양보 → 19-waypoint 주행 → 도킹 오차 0.50m.
→ `return_to_home/rth.py`

**Q. (심층) 확산 모델과 실환경 차이는?**
정상상태 가우시안 플룸의 2D 지면 근사(풍하 거리 비례 σ 성장, 1/(U·σ) 희석, 풍상 등방 누출, 시변 돌풍 ±20%·센서 노이즈). 실환경과의 차이 — 비정상 유동, 장애물 후류, 3D 성층 — 는 모델에 없으므로, 탐색기를 순간 구배에 의존하지 않는 구조(SURGE·백트래킹)로 설계해 모델 오차에 강인하게 했다.

## Digital Twin 시스템

**Q. 4요소의 역할과 실환경 반영은?**
Virtual Plant(월드+확산물리+설비 프로세스 시뮬), Robot Twin(URDF+gz_ros2_control+보행/복구), Inspection Data(판독·과열·농도 토픽), Monitoring(rosbridge 대시보드+Foxglove). 실환경 반영: 요구 치수의 복도/공장, 계단·험지, 아날로그 게이지(바늘 물리 구동+ground truth), 발열 배관, 가스 누출원+기류. → `docs/ARCHITECTURE.md` §1

**Q. 센서 데이터는 관제로 어떻게 전달·시각화되며 동기화는?**
전 노드 use_sim_time+/clock으로 시뮬 시간 일원화. 관제로는 원본 영상이 아닌 결과값(판독치·온도·농도)만 보내 대역폭을 수 KB/s로 유지하고, rosbridge 구독에 throttle(200~1000ms), 농도장은 0.5m/1Hz 다운샘플. 열화상 정합은 동일 센서 헤드의 depth 기하 기준이라 카메라 간 시간차 정합 오차가 원천 제거된다. → `ARCHITECTURE.md` §3

**Q. Sim2Real에서 고려한 차이는?**
시뮬 전용 요소(odometry↔상태추정기, gas_field↔실측 센서, set_pose 등)를 토픽 계약 뒤로 격리해 노드 교체만으로 이식되게 했다. 물리 엔진 의존 파라미터의 실증 사례로, 같은 제어기가 지지 방식(위치/토크)에 따라 전혀 다른 거동을 보인 stage2 실험이 있다 — 모델-플랜트 일치 검증이 Sim2Real의 핵심임을 보여준다. 도메인 랜덤라이제이션(마찰·질량·지연)은 RL 보너스의 계획 항목.

## 통합

**Q. 모듈 간 병목·충돌 방지를 위한 통신 설계와 자원 배분은?**
연속 스트림은 전부 Topic(결합도 최소 — 같은 odometry를 5개 노드가 독립 구독), Service는 시뮬 제어의 1회성 요청에만, 장시간 작업은 단일 로봇 구조에서 Action 대신 상태+이벤트 토픽(다중 로봇 확장 시 Nav2 Action 전환 지점 명시). cmd_vel은 중앙 mux 없이 우선순위 협조 중재: fall_recovery(관절 직접 점유) > rth(/rth_active) > seeker(알람 게이트) > mission. 200Hz 제어 루프와 10~15Hz 인지 루프를 노드로 분리해 비전 지연이 보행 주기에 영향을 주지 않게 했다. → `ARCHITECTURE.md` §3

**Q. 관제 전송의 실시간성·동기화는?**
위 동기화 답변과 동일 + 대시보드는 WebSocket(rosbridge)로 지연 수십 ms 수준, 시각화는 클라이언트 requestAnimationFrame으로 수신 주기와 분리.

## 전체 — 가장 어려웠던 문제

**타이머 중첩 버그**: 보행이 시간이 지날수록 열화(측방→후진, 후진→스핀)해 몇 주 분량의 격리 실험으로 '기생 결합'을 정량화하고 우회 설계까지 했으나, 진짜 원인은 디버그 타이머 추가 시 `__init__` 잔여 코드가 메서드로 흡수돼 **2초마다 100Hz 제어 타이머가 복제**된 것(실측 44개 누적). 수정 즉시 전 방향 보행이 정상화되고 통합 시나리오가 완주됐다. 교훈: 시간 경과형 제어 이상은 제어 이론보다 실행 기반(타이머·스레드)의 누적 결함을 먼저 의심할 것. 같은 실수의 재발(seeker)을 '시작 로그 부재/중복' 스모크 점검으로 잡았다. → `docs/REPORT.md` §3

**실산업 적용 시 추가 고려**: 상태추정(다리 오도메트리+IMU 융합), 방폭 인증·기능안전(ISO 13849), 통신 이중화(음영 시 로컬 자율), 배터리 열관리, 그리고 본 프로젝트가 보여준 것처럼 시뮬-실기 간 접촉·마찰 파라미터 검증 절차.
