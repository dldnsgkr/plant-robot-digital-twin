# LIP-MPC 예측 구간(Prediction Horizon) 튜닝 기록

실험: `python3 srbd_mpc.py` (dt=0.1s, 외란 = 초기 CoM 속도 0.35 m/s,
액추에이션 지연 40ms, 측정 노이즈 5mm, 입력 포화 ±0.10m)

| N | 구간(s) | 최대 변위(m) | 정착 시간(s) | 풀이 시간(µs) |
|---|---|---|---|---|
| 3 | 0.3 | 0.038 | 1.48 | 2.3 |
| 5 | 0.5 | 0.038 | 0.88 | 2.1 |
| **10** | **1.0** | **0.038** | **0.86** | **2.1** |
| 20 | 2.0 | 0.038 | 0.86 | 2.2 |
| 50 | 5.0 | 0.038 | 1.06 | 2.1 |
| 80 | 8.0 | 0.038 | 5.32 | 2.2 |

## 선정: N=10 (1.0초)

- LIP 시정수 √(h/g) ≈ 0.18s의 약 5배 — 이보다 짧으면(N=3) 포화 입력 하에서
  회복 여유를 과소평가해 정착이 느려지고, 이보다 길면 이득이 없다.
- 과제 스펙의 "5초 예측"(N=50)도 측정: 성능 이득 없음(1.06s로 소폭 저하).
  지연+포화가 있는 시스템에서 시정수 대비 과도하게 긴 구간은 초기 스텝의
  이득을 희석시킨다. N=80에서는 정착 5.32s로 뚜렷이 악화.
- 풀이 시간은 condensed 무제약 해(사전 계산된 이득 행렬) 덕에 N과 무관하게
  ~2µs — 실시간성 제약은 없으며, 선정 기준은 순수하게 제어 성능.

## 온라인 A/B 검증 — 정직한 결과: 현 스택에서는 역효과

**초기 검증의 무효화**: 처음 A/B에서 "지속 60N을 MPC가 완전 저지"라는 결과를
얻었으나, 이후 Pose_V→TFMessage 브리지가 엔티티 이름을 소실해 **MPC 노드가
상태를 전혀 수신하지 못했음**이 밝혀졌다(즉 ON≡OFF였고, 60N '밀림'은 마찰
경계 상황의 비재현적 우연). 오도메트리 플러그인으로 상태 공급을 고친 뒤
반복 시행으로 재검증한 결과:

| 시나리오 | MPC OFF | MPC ON (상태 수신 정상, 20Hz) |
|---|---|---|
| 기립, 측방 50N 지속 3s ×2회 | 밀림 0.00m, 전도 0 | 요동 후 **전도** |
| 기립, 측방 60N 지속 3s ×2회 | 밀림 0.00m, 전도 0 | **전도** |
| 보행 중 측방 30N×1s | 편차 0.19m, 생존 | **전도** |
| 보행 중 측방 40N×1s | 편차 0.32m, 생존 | **전도** |

**원인 분석 (심층 인터뷰 대비)**:
1. **플랜트-모델 불일치**: LIP은 "CoP 이동 → 중력 모멘트 → CoM 가속"을
   가정하지만, 위치제어로 강성 고정된 지지다리는 발 목표 이동이 **몸을
   직접 끌어당기는 운동학적 액추에이터**로 작용한다. 같은 u가 전혀 다른
   전달함수를 갖게 되어 설계 이득이 과대해진다.
2. **자기 가진 루프**: 발 이동 → 오도메트리 속도 스파이크 → MPC가 더 큰
   u → 진동 발산. 병렬로 작동하는 요 유지·자세 안정화 피드백과도 간섭.
3. 위치제어 스택의 정적 외란 저지력은 이미 기하·마찰로 충분(60N 지속에도
   0.00m) — 이 영역에서 MPC가 개선할 여지 자체가 작다.

**조치**: gait_controller의 CoP 주입은 `mpc_enable` 파라미터(기본 false)로
비활성. LIP-MPC가 실효를 내려면 **토크 제어 + 접촉 스케줄 기반 GRF 최적화**
(stage3 Convex MPC의 원래 형태)가 필요하다 — 이것이 본 실험의 결론이자
stage3의 존재 이유다.

## 구현 한계 (보고서 반영)

- CoP(지지다각형) 제약을 QP 제약이 아닌 해의 클리핑으로 처리 — 포화가 긴
  대형 외란에서는 준최적. stage3(C++ Convex MPC)의 개선 대상.
- 모델은 축별 분리 LIP — 롤/피치 동역학은 게이트 생성기의 자세 피드백에 위임.
